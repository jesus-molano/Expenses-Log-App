# Voice input for creating expenses in the Expense Log PWA: technical brief (2026-10-23)

Labels used below:
- **[V]** verified in official docs, browser-compat data or browser source code.
- **[S]** a secondary or third-party report.
- **[I]** my own inference or calculation.

Research limits: WebFetch could not resolve MDN, webkit.org, ai.google.dev, bugs.webkit.org or Firebase. Facts from those sites come from search-result excerpts, from raw GitHub copies of MDN content and browser-compat-data (BCD), or from caniuse data. Nothing was edited and no tests were run.

## 1. Recommendation

1. **Main path: option B.** Record with `MediaRecorder`, send the clip to the existing `/api/ai/parse-expenses` route, and have Gemini return the transcript and the expense drafts in one call.
   - This is the only option that works the same way in an installed iOS home-screen app, an installed Android Chrome app and desktop.
   - The manifest sets `display: "standalone"` (`src/app/manifest.ts`). On iOS 26, any site added to the home screen opens as a web app [S]. So iOS users will almost always hit the Web Speech gap described below.
2. **Optional extra: option C.** Where `SpeechRecognition` exists and the device is not iOS/WebKit, also show a live transcript in the text box. Treat this as a bonus, not a requirement.
3. **Do not build on Web Speech alone (option A).**

## 2. Option A: Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`)

**Browser support (from BCD) [V]**

| Browser | Support |
|---|---|
| Chrome, Edge, Chrome Android, Samsung Internet | Without prefix since 139 (Aug 2025); `webkit` prefix since 33 |
| Safari and iOS Safari | `webkit` prefix only, since 14.1 |
| Firefox | Only "preview", no stable release |

**On-device recognition [V]**
- `processLocally`, `available()` and `install()` arrived in desktop Chrome and Edge 139.
- Chrome Android and Safari do not have them.
- `phrases` (word biasing) is desktop Chrome 142 only. `available()` gained a `quality` option in Chrome 150.
- So on mobile there is no on-device mode you can request.

**Android quirk [V]:** on Chrome Android, `continuous` "can be set but has no effect" (crbug 41297427). Interim results are supported.

**Network and privacy [V].** MDN says: "On some browsers, like Chrome, using Speech Recognition on a web page involves a server-based recognition engine. Your audio is sent to a web service for recognition processing, so it won't work offline."
- On-device mode needs a one-time language-pack download per language.
- If the pack is missing, the error is `language-not-supported`.
- The `on-device-speech-recognition` Permissions-Policy defaults to `self`.

**How Safari implements it [V, WebKit source `WebSpeechRecognizerTask.mm`]**
- It wraps Apple's `SFSpeechRecognizer` with the dictation hint.
- It forces on-device processing when the device supports it.
- It raises `service-not-allowed` when the recognizer is unavailable.

**iOS home-screen app: not usable**
- caniuse's Safari note [V]: "Siri must be enabled… unavailable in SafariViewController and in web apps added to the Home Screen."
- WebKit bug 225298 (May 2021) [S]: an Apple engineer says it is "not available in SafariViewController and web apps added to Home Screen for now". The bug is marked RESOLVED LATER, last activity around March 2025.
- WebKit bug 321436 [S]: one report says it worked in standalone mode on iOS 26.6 but then hung silently after an `<audio>` element played (no result, no error). There is a later reproduction on iOS 27.0.
- A related hang (bug 317741) was reportedly fixed in June 2026 and shipped in iOS 27 [S, unverified].
- Conclusion: no reliable support.

**Other known problems [S]**
- On WebKit, running `getUserMedia` at the same time as recognition starves the recognizer of microphone audio.
- `continuous = true` can stop results from arriving.
- Brave blocks the API.
- Edge's on-device model is behind a flag in Canary/Dev 150.0.4076 and later, and caniuse notes that Edge "events don't fire".

**Verdict:** works well in Chrome on Android and desktop, which send audio to Google. It is absent or flaky in exactly the context where this app is used most.

## 3. Option B: record with MediaRecorder and let Gemini transcribe and understand

**Browser support (from BCD) [V]**

| Browser | `MediaRecorder` and `isTypeSupported` |
|---|---|
| Safari | 14.1 |
| iOS Safari | 14 |
| Chrome | 47 (audio from 49) |
| Firefox | 25 |

**Recording formats**
- iOS has historically recorded MP4/AAC only (webkit.org "MediaRecorder API" post) [V].
- iOS 18.4 and later can also record WebM/Opus (WebKit bug 290223 reporter; TestMu guide) [S].
- Chrome produces `audio/webm;codecs=opus` [I, standard behaviour].
- Do not sniff the user agent. Try these in order with `MediaRecorder.isTypeSupported`:
  1. `audio/webm;codecs=opus`
  2. `audio/mp4;codecs=mp4a.40.2`
  3. `audio/mp4`
  4. `audio/ogg;codecs=opus`
- Send whatever the browser reports in `recorder.mimeType` [I].

**What Gemini accepts**
- Firebase AI Logic's input requirements and the FlutterFire MIME list include `audio/webm`, `audio/mp4`, `audio/m4a`, `audio/aac`, `audio/opus`, `audio/ogg`, `audio/wav`, `audio/mpeg` and `audio/flac` [V/S].
- Older Gemini docs list only WAV, MP3, AIFF, AAC, OGG and FLAC. Test both WebM and MP4 against the model you choose.
- Audio costs 32 tokens per second [V/S]. One audio file per request [S].
- Google's January 2026 blog says the inline payload limit rose from 20 MB to 100 MB [V].

**Hosting limit [V]:** Vercel functions reject request bodies over 4.5 MB (HTTP 413), on every plan.

**Size and cost [I]**
- A 20-second clip is about 80 KB as Opus at 32 kbps, or about 160 KB as AAC at 64 kbps. Base64 adds about a third. Either way it is far below every limit.
- 20 s × 32 tokens/s = 640 tokens. At gemini-3.8-flash's $0.75 per million input tokens (Google Cloud pricing), that is about $0.0005 per clip.
- Use a 30-second automatic cap and reject clips shorter than about 0.7 s.

**Microphone permission in installed iOS apps [S]**
- Home-screen apps have no per-site permission setting, so iOS asks again on every cold launch.
- Navigation inside one launch may also reset the permission.
- Sources: WebKit bug 215884; the seeni project issue #69 (October 2026); the times-tables issue #44 says Apple called persistent permission an "unfiled request" in February 2026.
- Design for this: explain the prompt before triggering it, and keep the stream alive while the sheet is open rather than stopping and restarting it.

**Offline [I]:** recording works offline, but understanding the clip needs the network. The service worker already sends API calls to the network only. If offline, keep the clip in memory and show a Retry button. Do not build an IndexedDB queue in v1.

**Gemini setup issues in the current route.** These probably explain part of "Gemini funciona fatal":
- **Default model.** The app defaults to `gemini-2.5-flash` (`src/app/api/ai/parse-expenses/route.ts`, `.env.example`).
  - Since 2026-09-18, Google only serves the 2.5 models to accounts that used them before.
  - For new projects it recommends 3.5 Flash-Lite or 3.8 Flash.
  - On Vertex AI, the 2.5 models retire in October 2026. [S, via the Gemini changelog]
  - If the key belongs to a new project, every call likely fails and silently falls back to the local parser. Check the exact model ID on Google's models page.
- **API key in the URL.** The route sends `?key=` in the URL. Move it to the `x-goog-api-key` header.
- **No schema.** The prompt asks for a JSON shape in free text. Gemini 2.5 and later accept `generationConfig.responseJsonSchema` together with `responseMimeType` [S, Vercel AI SDK PR #18325]. Generate the schema from Zod with `z.toJSONSchema`.
- **Missing context.** Add today's date, time zone, currency, the user's own category list, and the recurrence enum to the prompt.
- **Timeout.** 8 s is too tight for audio. Use about 15 s.
- **Only one result used.** The hook keeps only `expenses[0]`, even though the route can return up to 10.

**Privacy [V/S]:** under the Gemini API Additional Terms, free-tier inputs may be used to improve Google's products and may be seen by human reviewers. Paid-tier inputs are not. Add a one-time notice ("El audio se envía a Google Gemini para interpretarlo; no se guarda") and do not store the clips.

## 4. Option C: hybrid, and when each path applies [I]

| Context | Path |
|---|---|
| iOS, Safari tab or home-screen app | B only |
| Android Chrome, tab or installed | B by default. Live transcript (A) is optional; it still goes to Google, and `continuous` is ignored |
| Desktop Chrome or Edge | A, then the existing text parser. B as fallback |
| Firefox, Brave, no `SpeechRecognition` | B |
| No `MediaRecorder` or `getUserMedia`, not logged in, or no AI key | Hide the mic, or show it disabled with a reason. Audio has no local parser to fall back on |

On WebKit, never run A and B at the same time.

## 5. UX patterns for voice entry

**Tap to start, tap to stop. Not press-and-hold.**
- Holding a button is hard for people with motor impairments and for screen-reader users.
- WCAG 2.2 criterion 2.5.2 (pointer cancellation) favours actions that complete on release, with a way to cancel.
- Press-and-hold with slide-to-cancel, as in WhatsApp, could be added later as a shortcut. [V for WCAG, I for the conclusion]

**Always show a confirmation step before saving**
- Expense apps commonly treat the spoken result as a draft to review: WiseFlow, TrackDad, Money Vault ("the transcript is used to propose structured actions, and the user confirms them before saving"), CapKin ("The AI proposes. You decide.") [S].
- MonAi auto-saves voice entries by default, with an opt-out. Avoid that for recurring bills.
- Similar-sounding numbers such as "quince" and "cincuenta" corrupt totals while looking plausible, so highlight the amount field [S].

**Proposed flow in `QuickCapture` [I]**
1. Mic button (`IconButton`, lucide `Mic`) next to the text input, with `aria-pressed` and `aria-label="Dictar gasto"`.
2. While recording: elapsed time, a simple level meter (Web Audio `AnalyserNode`, static if the user prefers reduced motion), a `Square` stop button and a Cancel button.
3. While processing: `Loader2` spinner.
4. Show "Hemos entendido: …" with the transcript, editable, so the user can re-analyse it as text.
5. Open the existing `ExpenseForm` pre-filled, or a list of drafts when several expenses were spoken.
6. Announce status changes through an `aria-live="polite"` region.
7. Show a hint example: "Netflix 12,99 al mes el día 5".

**Error states to handle [I]**

| Situation | Message or behaviour |
|---|---|
| `NotAllowedError` | How to re-enable: iOS Ajustes › Safari › Micrófono, or reload, plus a retry button |
| `NotFoundError` | No microphone found |
| `NotReadableError` | Microphone in use by another app |
| Clip too short | Ask to try again |
| Empty result | "No te he entendido" |
| Offline | Keep the clip and offer Retry |
| Timeout, quota, rate limit | Fall back to the transcript if there is one, otherwise to manual entry |
| App goes to background | Stop and stop the tracks |

## 6. Implementation outline (follows AGENTS.md layers) [I]

**Pure helpers, with Vitest tests**
- New `src/features/expenses/lib/voice-support.ts`:
  - `pickRecorderMimeType(isTypeSupported)`
  - `getVoiceCapability({ hasMediaRecorder, hasGetUserMedia, isSecureContext, isWebKit, aiAvailable })` returning `"record" | "dictate" | "unavailable"`

**Recording hook**
- New `src/features/expenses/hooks/use-voice-capture.ts`, a state machine: idle → permission → recording → processing → done or error.
- Request audio with `{ channelCount: 1, echoCancellation, noiseSuppression, autoGainControl }` and `audioBitsPerSecond: 32000`.
- 30-second cap; stop on `visibilitychange`.

**Optional live dictation**
- New `use-live-dictation.ts`, Chromium only. It writes interim results into `quickText`.

**Server route**
- Extend `src/app/api/ai/parse-expenses/route.ts` to also accept `multipart/form-data`:
  - an `audio` Blob of at most 1 MB from a MIME allow-list
  - an optional `lang` field
- Keep the same authentication and rate limit. Consider a lower per-minute limit for audio.
- Gemini parts: `[{ inlineData: { mimeType, data: base64 } }, { text: instruction }]`.
- Response schema: `{ transcript, expenses[] }`, temperature 0, timeout about 15 s.
- For audio there is no local fallback: return `reason` and `transcript: null`.
- Extend `route.test.ts` to cover the audio cases.

**Other files**
- Add new strings to `src/shared/i18n` in both es and en.
- Document `GEMINI_API_MODEL` with the updated default in `.env.example`.

**Real-device test matrix**
- iPhone on iOS 26.x and 27.x, Safari tab and home-screen app.
- Android Chrome, tab and installed.
- Desktop Chrome.
- For each, check: first prompt and re-prompts, which MIME type was chosen, Gemini accepting both WebM and MP4, and Spanish amounts ("doce con noventa y nueve", "mil doscientos").
